00 Overview

I build small, playable games end to end: gameplay code, systems, and the 3D assets that go in them.

Because I model in Blender and program the engine side myself, I can take a mechanic from a sketch to a working in-engine build without waiting on a hand-off.

I prototype early, test on real hardware, and cut features that don't make the game better. Short builds and honest playtests over long design documents.

01 Currently Building

PROJECT: untitled_physics_prototype BUILD: 0.3.x · STATE: prototype

A third-person movement and physics-interaction prototype. The goal is a character controller that feels responsive on keyboard and gamepad, and a small set of objects the player can push, carry and stack without the physics falling apart.

  • [DONE]Character controller with coyote time, jump buffering and slope handling.
  • [DONE]Blender-to-engine pipeline: modular props, LODs, consistent scale and pivot conventions.
  • [WIP]Grab / carry system with weight-based movement penalties.
  • [WIP]Camera collision and framing in tight interior spaces.
  • [NEXT]Graybox test level and a short playtest round to tune feel.

03 How I Work (Remote)

  1. Async by default.

    Written updates at the end of each working day: what changed, what's blocked, what's next. No need to be online at the same time to stay in sync.

  2. Version control discipline.

    Git with small, descriptive commits, feature branches and pull requests. Large binary assets handled with Git LFS.

  3. Clear documentation.

    Readable code, short READMEs for each system, and notes on asset naming and import settings so the next person can pick things up.

  4. Fluent English communication.

    Comfortable with written specs, code review comments and video calls. I ask questions early instead of guessing.
